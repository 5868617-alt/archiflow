# ארכיטקטורה

```
דפדפן (site/index.html, React)
   │  fetch + JWT של המשתמש
   ▼
Supabase  qbwaqngxdgmqgddxcuzv
   ├─ Auth (GoTrue)          הרשמה, אימות מייל, התחברות, איפוס סיסמה
   ├─ PostgREST              טבלאות (RLS) ופונקציות RPC
   ├─ Storage                דליים פרטיים: plans, documents, receipts
   ├─ pg_cron                משימות שעתיות ויומיות, ושליחת תור המיילים כל דקה
   └─ Edge Function          send-emails → Resend (רק כשיש RESEND_API_KEY)
```

אין שרת ביניים. הדפדפן מדבר עם Supabase בעזרת המפתח הציבורי והטוקן של המשתמש, וכל החלטת הרשאה מתקבלת במסד.

## האתר
- **בנייה:** `build.mjs --live` אורז את `src/live/main.tsx` עם esbuild לקובץ HTML אחד. React 18.3.1 נטען מ-cdnjs.
- **ניתוב:** hash (`#/projects/…`). טוקנים של אימות מייל ואיפוס סיסמה מגיעים ב-hash ונקלטים בטעינה או ב-`hashchange`.
- **לקוח Supabase:** `src/live/client.ts` הוא לקוח `fetch` קטן ל-Auth, PostgREST ו-Storage, ומרענן טוקנים לפני שהם פגים.
- **הגדרות:** `src/live/config.ts` מכיל כתובת ומפתח ציבורי. אפשר לדרוס אותם עם `window.__AF_CONFIG`.

## טעינת נתונים
- `my_context()` מחזירה למשתמש את המשרדים, את פרטי הלקוח שהוא מקושר אליו ואת הדגל Super Admin.
- `app_snapshot(p_office)` מחזירה בקריאה אחת את כל מה שהמשתמש רשאי לראות במשרד. היא `security invoker`, ולכן RLS חל עליה.
- `src/live/map.ts` ממפה את התשובה למודל של הממשק (`src/data/types.ts`) ומתרגם קודים באנגלית לתוויות בעברית.
- הנתונים נטענים מחדש אחרי כל כתיבה, כשחוזרים ללשונית, וכל 2 דקות.

## כתיבה
- המסכים קוראים `run(A.action, …)`, כמו בגרסת ההדגמה.
- `src/live/store.tsx` מחיל את השינוי מיד על המסך, ובמקביל שולח אותו למסד דרך תור.
- `src/live/sync.ts` משווה בין המצב לפני השינוי לאחריו, ומתרגם את ההבדל לקריאות מסד:
  - **שינויים רגילים:** insert/update/delete ישירים, עם `Prefer: return=minimal`.
  - **פעולות רגישות** הולכות לפונקציות שרת:
    - `set_project_status`
    - `request_approval`, `decide_approval`, `cancel_approval`
    - `invite_member`, `invite_client_contact`, `resend_invitation`
    - `send_purchase_order`, `send_fee_request`, `send_meeting_email`, `send_approval_reminder`
    - בקשות מנוי, `apply_template`, `annotation_to_task`
  - **פעולות שקיימות רק בהדגמה** (`DEMO_ONLY`, למשל סימולציית חיוב) חסומות בגרסה המחוברת.
- אם הכתיבה נכשלת, המשתמש מקבל הודעה בעברית והמסך חוזר למצב שבמסד.
- מזהים חדשים נוצרים בלקוח (`crypto.randomUUID`). כך אין צורך לקרוא את השורה אחרי הכתיבה, ש-RLS לפעמים לא מאפשר באותה פקודה.

## קבצים
- **נתיב:** `{office_id}/{project_id|office}/{uuid}/{שם-בטוח}`.
- **העלאה:** קודם הקובץ, ואחר כך רשומת המטא-דאטה. קריאת קובץ מותרת רק אם קיימת רשומה שהמשתמש מורשה לראות.
- **פתיחה:** קישור חתום לזמן קצר.
- **שרטוטי PDF** מוצגים בדפדפן עם pdf.js 3.11.174 (העמוד הראשון), בתוך אותה מערכת קואורדינטות של הצופה. לכן נעצים ומדידות עובדים על הקובץ האמיתי.
- **כיול מדידה** נשמר בתגיות השרטוט (`cal:<גרסה>:<מטר ליחידה>`).

## מיילים ומשימות מתוזמנות
- **מיילים:** פונקציות השרת מוסיפות מיילים ל-`email_outbox`. כל דקה `private.trigger_email_sender()` קורא ל-`send-emails`, אם יש מיילים בתור.
- **אימות הקריאה:** הפונקציה מאמתת את הקורא מול סוד ב-Vault (`email_sender_config`).
- **בלי `RESEND_API_KEY`** היא מחזירה "skipped", ולא נשלח כלום.
- **שעתי:** מחזור חיי מנוי (ניסיון שפג, שנמוך בסוף תקופה) ותפוגת הזמנות.
- **יומי (05:07 UTC):** שכר טרחה באיחור ותזכורות אישורים.

## גרסת ההדגמה
`node build.mjs` בונה גרסה עם נתונים בדויים ב-localStorage, בלי מסד, ועם החלפת תפקיד חופשית. היא שימושית להצגה ולבדיקת עיצוב, וכל מה שמדומה בה מסומן.
